# Устройство проекта

NARD представляет собой статическое приложение на TypeScript и Vite. Все данные партии находятся в памяти вкладки браузера. Серверного API, базы данных, аккаунтов и переменных окружения нет.

## Файлы и ответственность

| Файл | Ответственность |
| --- | --- |
| `index.html` | Корневой элемент приложения и метаданные страницы. |
| `src/engine.ts` | Чистые функции правил: расстановка, доступные перемещения, применение хода, оценка результата. От DOM не зависит. |
| `src/main.ts` | Состояние партии, броски, куб, счёт, отрисовка и обработчики действий пользователя. |
| `src/style.css` | Цвета, игровое поле и адаптивная раскладка. |
| `src/engine.test.ts` | Тесты игровых ситуаций на базе `node:test`. |

## Модель доски

`Board.points` содержит 24 числа. Индекс `0` соответствует видимому пункту 1, индекс `23` соответствует пункту 24. Положительное число означает количество светлых фишек, отрицательное означает количество тёмных, ноль означает пустой пункт. `Board.bar` хранит сбитые фишки, `Board.off` хранит выведенные фишки отдельно для каждого игрока.

`Move` содержит источник `from`, назначение `to` и число кости `die`. Источник может быть индексом пункта или `'bar'`. Назначение может быть индексом пункта или `'off'`. Функция `applyMove` возвращает новую доску и не изменяет переданный объект.

## Проверка хода

1. `movesForDie` находит допустимые одиночные перемещения для одной кости с учётом бара, закрытых пунктов и вывода.
2. `legalSequences` перебирает оба порядка разных костей или четыре одинаковых числа дубля и строит все допустимые последовательности текущего броска.
3. Из них остаются последовательности с максимальным числом использованных костей. Если разные кости позволяют только один ход, остаются варианты со старшей костью.
4. `firstMoves` отдаёт допустимые первые шаги для подсветки поля. После выбора шага интерфейс оставляет только последовательности, начинающиеся с него.

Такой порядок важен: допустимость отдельного перемещения ещё не означает, что с него разрешено начинать весь ход.

## Состояния партии

`src/main.ts` использует следующие фазы:

| Фаза | Что доступно |
| --- | --- |
| `opening` | Определение первого игрока. |
| `roll` | Бросок костей или предложение удвоения до броска. |
| `offer` | Принятие или отказ от предложенного удвоения. |
| `move` | Перемещения, отмена последнего шага и завершение хода. |
| `over` | Результат и начало новой партии. |

История отмены хранит снимки доски и оставшихся допустимых последовательностей только для текущего хода. При завершении хода она очищается. `score` живёт в памяти страницы и сохраняется при нажатии «Новая партия», но сбрасывается при обновлении вкладки.

Кости генерируются через `crypto.getRandomValues`. Перед переводом случайного числа в диапазон 1–6 используется отбрасывание значений, чтобы не создавать смещения из-за остатка от деления.

## Разработка и проверки

```bash
npm ci
npm test
npm run build
```

`npm test` проверяет расстановку, сбивание и вход с бара, правило старшей кости, максимальное использование костей, вывод и подсчёт результата. `npm run build` сначала запускает проверку типов TypeScript, затем создаёт статическую сборку в `dist/`. Интерактивное управление и внешний вид требуют отдельной ручной проверки в браузере после изменения `src/main.ts` или `src/style.css`.

Перед расширением до сетевой игры потребуется сервер, который будет владеть состоянием партии, бросками и проверкой ходов. Текущий браузерный контроллер рассчитан на двух игроков за одним устройством и не защищает сетевую игру от расхождения состояний.
