# NARD

Веб-игра в классические короткие нарды. Есть локальная игра вдвоём, партия против бота, наблюдение за двумя ботами и онлайн-партия между аккаунтами по приглашению. Локальные режимы работают в браузере. Для онлайн-режима нужен сервер Node.js.

## Быстрый запуск через Docker

```bash
docker compose up -d --build nard
docker compose ps
```

Откройте `http://127.0.0.1:7000/`. Данные аккаунтов, партий и журналов сохраняются в отдельных Docker volumes. Первый администратор создаётся в остановленном контейнере, точные команды и настройка HTTPS для VPS приведены в [инструкции Docker](docs/docker.md).

## Разработка без Docker

Требуются Node.js 22.12 или новее и npm. Из корня проекта:

```bash
npm ci
npm run dev
```

Откройте адрес `Local`, который напечатает Vite. Обычно это `http://127.0.0.1:5173/`. Если порт занят, используйте адрес из вывода команды.

Онлайн-страница находится по адресу `/online.html`. Для первого входа администратор создаётся из терминала при остановленном сервере:

```bash
npm run admin:create -- Admin
```

Команда покажет личный токен один раз. Скопируйте его в безопасное место и введите на странице входа. Дальше администратор создаёт игроков в админ-панели и выдаёт им токены. Самостоятельной регистрации нет. Токены действуют до перевыпуска или отключения аккаунта; сессия браузера действует 7 дней.

Перевыпуск токена завершает сессии игрока, но сохраняет его партию. Отключение аккаунта завершает незаконченные партии в пользу соперника.

Для VPS доступны [Docker Compose](docs/docker.md) и [запуск через systemd](docs/deploy-vps.md). Само развёртывание выполняет владелец сервера.

## Как играть в интерфейсе

1. Выберите режим в боковой панели: «Два игрока», «Против бота» или «Бот против бота». Смена режима начинает новую сессию и сбрасывает счёт.
2. В режиме с человеком нажмите «Определить первый ход». Игра бросит по одной кости за каждого игрока и покажет, кто начинает. В режиме бот против бота партия начинается автоматически.
3. В свой ход выберите фишку на поле или бар, если там есть ваши фишки. Допустимые пункты подсветятся. Нажмите пункт назначения или выберите ход с конкретной костью в боковой панели.
4. Когда все доступные ходы сыграны, нажмите «Завершить ход». Следующий игрок бросает кости. Если ходов нет, эта же кнопка передаёт очередь сопернику.
5. До завершения своего хода кнопка «Отменить ход» возвращает последнее перемещение. Её можно нажимать несколько раз. Победа фиксируется после вывода всех 15 фишек и нажатия «Завершить ход».

Фишки на пунктах можно также перетаскивать мышью. Для бара и на сенсорном экране используйте нажатия. Если один пункт назначения доступен для разных костей, выберите нужную кость в боковой панели.

В режиме «Против бота» человек играет светлыми, бот тёмными. Бот сам бросает кости, делает ходы и решает, предлагать или принимать удвоение. Настройки сложности нет. В режиме «Бот против бота» игра продолжается партия за партией; кнопка «Пауза» останавливает автоматические действия, «Продолжить» возобновляет их. «Новая партия» сохраняет счёт в текущем режиме.

Для партии с другим человеком откройте «Онлайн», войдите по личному токену и выберите игрока из списка тех, кто сейчас в сети. Адресат принимает приглашение, после чего сервер определяет первый ход. Броски, ходы, удвоение и результат проверяет сервер. Если соединение прервётся, откройте ту же партию из лобби после повторного входа. В онлайн-партии нет отмены подтверждённого хода.

В локальной и сетевой партии кости лежат в центральной полосе поля: первый бросок показывает по одной кости каждого цвета, следующие броски показывают обе кости на стороне бросившего. Числа остаются видны после анимации, в том числе после завершения хода. В сетевой партии результат приходит с сервера и коротко анимируется у обоих участников. Если в системе включено уменьшение анимации, значения отображаются сразу.

Броски, ходы, сбивания, удвоения и результаты появляются в «Журнале игры» под кнопками управления. В нём показаны последние 150 событий, новые сверху. Отмена удаляет отменённый ход из экранного журнала и добавляет запись об отмене.

Полное описание реализованных правил и подсчёта очков: [Правила игры](docs/rules.md).

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запускает локальный сервер разработки на `127.0.0.1`. |
| `npm test` | Проверяет правила, бота, файловый журнал и серверную онлайн-партию. |
| `npm run build` | Проверяет типы, собирает серверный движок и страницы в `dist/`. |
| `npm start` | Запускает сервер собранной игры на `127.0.0.1:4173` без Docker. Перед первым запуском требуется `npm run build`. |
| `npm run admin:create -- <имя>` | Создаёт первого администратора и показывает его токен один раз. |
| `npm run admin:rotate -- <имя>` | Перевыпускает токен администратора и завершает его сессии. Запускайте при остановленном сервере. |

`npm run dev` тоже записывает события в файл. Файлы создаются в `logs/game-events-YYYY-MM-DD.jsonl`, дата в имени указана по UTC. Каждая строка содержит время `at` в ISO 8601, идентификатор вкладки `session`, номер партии `game`, тип события `kind` и текст `text`. Папка `logs/` исключена из Git. При необходимости путь можно изменить переменной `GAME_LOG_DIR`. Журнал в файле сохраняет все события, включая ход и последующую отмену, и не сбрасывается при смене режима или обновлении страницы.

Для онлайн-партий и записи в файл запускайте игру через Docker Compose, `npm run dev` или `npm start`. При размещении только сборки `dist/` на статическом хостинге работают локальные режимы и экранный журнал, но онлайн-режим и серверная запись в файл недоступны. На публичном VPS задайте `PUBLIC_ORIGIN` с адресом HTTPS-сайта; тогда файловый журнал локальных режимов принимает записи только от вошедших пользователей. На локальном адресе `127.0.0.1` запись доступна и без входа. Шрифты загружаются из Google Fonts при наличии сети; при недоступности сети применяются системные шрифты.

## Состав проекта

- `src/engine.ts`: состояние доски, допустимые ходы, применение ходов и результат партии.
- `src/bot.ts`: выбор хода и решения по кубу удвоения.
- `src/bot.worker.ts`: расчёт хода вне основного потока страницы.
- `src/main.ts`: ход партии, куб удвоения, счёт и взаимодействие с интерфейсом.
- `src/online.ts`: вход, лобби, приглашения, онлайн-поле и админ-панель.
- `server/multiplayer.mjs`: аккаунты, приглашения, присутствие и серверная партия.
- `server/store.mjs`, `server/auth.mjs`: постоянное состояние и вход по токену.
- `vite.config.ts`, `server.mjs`, `server/log-api.mjs`: HTTP, запись событий и раздача собранной игры.
- `src/style.css`: оформление поля и адаптивная раскладка.
- `src/engine.test.ts` и `src/bot.test.ts`: проверки правил и автоматической партии.

Подробнее о модели данных, ходе партии и проверках: [Устройство проекта](docs/architecture.md).

## Границы текущей версии

Нет матча до заданного числа очков. Счёт локальных режимов и их экранный журнал живут в памяти вкладки: обновление страницы начинает новую локальную сессию. Онлайн-партии и аккаунты сохраняются в `data/state.json` на сервере; проект рассчитан на один серверный процесс и небольшую частную установку. Файловый журнал хранится на том же сервере. Бот использует оценку позиции и поиск ответных ходов, а не турнирный движок с обученной нейросетью. Дополнительные турнирные правила перечислены в [Правилах игры](docs/rules.md).
