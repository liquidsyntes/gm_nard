# Устройство проекта

NARD использует TypeScript, Vite и сервер Node.js. Локальные партии находятся в памяти вкладки. Онлайн-аккаунты, приглашения, сессии и партии сохраняются сервером в `data/state.json`. События также пишутся в JSONL-файл.

## Файлы и ответственность

| Файл | Ответственность |
| --- | --- |
| `index.html` | Корневой элемент приложения и метаданные страницы. |
| `src/engine.ts` | Чистые функции правил: расстановка, доступные перемещения, применение хода, оценка результата. От DOM не зависит. |
| `src/bot.ts` | Оценка позиции, выбор последовательности ходов и решения по кубу. |
| `src/bot.worker.ts` | Запуск расчёта бота в Web Worker, без блокировки поля. |
| `src/main.ts` | Состояние партии, броски, куб, счёт, отрисовка и обработчики действий пользователя. |
| `online.html`, `src/online.ts`, `src/online.css` | Вход, лобби, админ-панель и онлайн-поле. |
| `vite.config.ts` | Подключает тот же API к серверу разработки Vite. |
| `server.mjs` | Отдаёт сборку `dist/` и API при `npm start`. |
| `server/multiplayer.mjs` | Серверная проверка входа, приглашений, бросков, ходов и удвоений. |
| `server/store.mjs`, `server/auth.mjs`, `server/admin-cli.mjs` | Хранение состояния, токены, сессии и первичная настройка администратора. |
| `server/log-api.mjs` | Проверяет события и последовательно дописывает JSONL-файл в `logs/`. |
| `src/style.css` | Цвета, игровое поле и адаптивная раскладка. |
| `src/engine.test.ts`, `src/bot.test.ts`, `server/log-api.test.mjs` | Тесты правил, автоматической партии и файловой записи на базе `node:test`. |

## Модель доски

`Board.points` содержит 24 числа. Индекс `0` соответствует видимому пункту 1, индекс `23` соответствует пункту 24. Положительное число означает количество светлых фишек, отрицательное означает количество тёмных, ноль означает пустой пункт. `Board.bar` хранит сбитые фишки, `Board.off` хранит выведенные фишки отдельно для каждого игрока.

`Move` содержит источник `from`, назначение `to` и число кости `die`. Источник может быть индексом пункта или `'bar'`. Назначение может быть индексом пункта или `'off'`. Функция `applyMove` возвращает новую доску и не изменяет переданный объект.

## Проверка хода

1. `movesForDie` находит допустимые одиночные перемещения для одной кости с учётом бара, закрытых пунктов и вывода.
2. `legalSequences` перебирает оба порядка разных костей или четыре одинаковых числа дубля и строит все допустимые последовательности текущего броска.
3. Из них остаются последовательности с максимальным числом использованных костей. Если разные кости позволяют только один ход, остаются варианты со старшей костью.
4. `firstMoves` отдаёт допустимые первые шаги для подсветки поля. После выбора шага интерфейс оставляет только последовательности, начинающиеся с него.

Такой порядок важен: допустимость отдельного перемещения ещё не означает, что с него разрешено начинать весь ход.

## Состояния партии

`src/main.ts` использует следующие фазы:

| Фаза | Что доступно |
| --- | --- |
| `opening` | Определение первого игрока. |
| `roll` | Бросок костей или предложение удвоения до броска. |
| `offer` | Принятие или отказ от предложенного удвоения. |
| `move` | Перемещения, отмена последнего шага и завершение хода. |
| `over` | Результат и начало новой партии. |

История отмены хранит снимки доски и оставшихся допустимых последовательностей только для текущего хода. При завершении хода она очищается. `score` живёт в памяти страницы и сохраняется при нажатии «Новая партия», но сбрасывается при обновлении вкладки.

Экранный журнал хранит последние 150 событий, новые показываются сверху. `record` отправляет каждое событие на `/api/logs` в порядке возникновения. Сервер добавляет собственное время и сохраняет все события в дневной файл `logs/game-events-YYYY-MM-DD.jsonl`. Каждая строка представляет отдельный JSON-объект с полями `at`, `session`, `game`, `kind`, `text`. При отмене экранная запись хода удаляется, а в файле сохраняются исходный ход и отдельная запись об отмене. Статус записи показывается в интерфейсе. Переменная `GAME_LOG_DIR` меняет каталог файлов; по умолчанию используется `logs/` в проекте.

`mode` принимает значения `local`, `bot` и `demo`. В `bot` автоматизированы тёмные фишки, в `demo` обе стороны. Переключение режима сбрасывает счёт и начинает новую партию. В `demo` после результата автоматически начинается следующая партия; флаг `paused` останавливает запланированные действия. При смене партии ответ уже запущенного расчёта бота игнорируется по номеру версии игры.

## Как выбирает ход бот

Бот получает от `legalSequences` только полностью допустимые варианты. Он оценивает результирующие доски по расстоянию до вывода, выведенным и сбитым фишкам, закрытым пунктам, цепочкам пунктов и уязвимым одиночным фишкам. Позиции с одинаковым итоговым состоянием объединяются. Для пяти лучших по быстрой оценке вариантов бот перебирает все 21 различный бросок соперника с весами вероятности и учитывает его лучший ответ. Уровень сложности один, настройки нет.

Расчёт выполняется в Web Worker. Если Worker недоступен, предусмотрен расчёт в основном потоке. Предложение и принятие удвоения бот решает по приблизительной оценке шанса на победу; это эвристика, а не точный расчёт игровой стоимости позиции. Бот не является профессиональным турнирным движком.

Кости генерируются через `crypto.getRandomValues`. Перед переводом случайного числа в диапазон 1–6 используется отбрасывание значений, чтобы не создавать смещения из-за остатка от деления.

## Онлайн-партия

Администратор создаёт аккаунт, а сервер генерирует личный случайный токен. В файле состояния хранится только SHA-256 хэш токена. После входа сервер выдаёт случайную сессию на 7 дней через cookie `HttpOnly` и `SameSite=Strict`; при HTTPS дополнительно используется `Secure` и префикс `__Host-`. Перевыпуск токена завершает действующие сессии пользователя. Самостоятельной регистрации нет.

Открытое соединение Server-Sent Events отмечает пользователя как находящегося в сети. При изменении приглашения или партии сервер рассылает сигнал обновления, а браузер запрашивает актуальное состояние через API. Приглашение можно отправить только подключённому игроку, срок действия приглашения 5 минут.

Сервер выбирает начальный бросок и все следующие броски через `crypto.randomInt`. Для каждого предложенного хода он пересчитывает `legalSequences` из общего движка и проверяет текущего игрока, фазу и версию партии. При подтверждении хода состояние атомарно записывается в `data/state.json`, затем участникам приходит сигнал обновления. Повтор действия со старой версией отклоняется. Онлайн-ходы необратимы; при выходе из браузера игрок может вернуться к партии после входа. Один аккаунт может участвовать только в одной незавершённой онлайн-партии.

У каждого серверного броска есть `lastRoll.id`, цвет игрока, время и два числа. Браузер анимирует только новый идентификатор и после анимации показывает значения сервера. Обновления ходов с тем же идентификатором не перезапускают бросок. При системном предпочтении уменьшенной анимации промежуточные кадры пропускаются.

Маршруты, параметры действий и ответы описаны в [справочнике онлайн API](online-api.md).

Хранилище рассчитано на один процесс Node.js. Файл состояния заменяется атомарно, записи внутри процесса выполняются последовательно. Несколько процессов с одним каталогом данных и горизонтальное масштабирование не поддерживаются. Для переноса или восстановления копируйте каталог данных и файловый журнал; порядок описан в [инструкции VPS](deploy-vps.md).

## Разработка и проверки

```bash
npm ci
npm test
npm run build
npm start
```

`npm test` проверяет расстановку, сбивание и вход с бара, правило старшей кости, максимальное использование костей, вывод, подсчёт результата, работу бота, файловый журнал и серверную онлайн-партию от приглашения до результата. `npm run build` проверяет типы, создаёт серверную JavaScript-версию движка и обе страницы в `dist/`. Интерактивное управление и внешний вид требуют отдельной ручной проверки в браузере после изменения клиентского интерфейса.

Для нескольких серверных процессов потребуется заменить файловое хранилище и локальную карту присутствия общими сервисами. Текущая установка рассчитана на один процесс Node.js.
