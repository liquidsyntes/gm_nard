# Онлайн API

Все маршруты находятся на том же домене, что и игра. Ответы имеют формат JSON. Ошибка возвращает HTTP-статус и объект `{"error":"..."}`. После входа браузер передаёт сессионную cookie автоматически. Личный токен отправляется только в теле запроса входа и не включается в URL.

## Вход и администрирование

| Метод и маршрут | Назначение |
| --- | --- |
| `POST /api/auth/login` | Вход по `{"token":"nard_..."}`. Возвращает пользователя и устанавливает сессионную cookie на 7 дней. |
| `GET /api/auth/me` | Текущий пользователь или `401`, если сессия отсутствует. |
| `POST /api/auth/logout` | Завершить текущую сессию и очистить cookie. |
| `GET /api/admin/users` | Список пользователей без хэшей и токенов. Только администратор. |
| `POST /api/admin/users` | Создать игрока по `{"name":"..."}`. Возвращает личный токен только в этом ответе. |
| `POST /api/admin/users/:id/rotate` | Перевыпустить токен игрока и завершить его сессии. Новый токен возвращается только в этом ответе. |
| `POST /api/admin/users/:id/toggle` | Отключить или включить игрока. Отключение завершает его активную партию в пользу соперника. |

Токены генерируются из 32 случайных байт. В файле `data/state.json` хранятся их SHA-256 хэши. Аккаунт первого администратора создаётся CLI-командой при остановленном сервере, остальные аккаунты создаются в админ-панели.

## Присутствие и приглашения

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/live` | Поток Server-Sent Events. Открытое соединение означает, что пользователь в сети. Событие `refresh` предлагает клиенту снова запросить лобби или партию. |
| `GET /api/lobby` | Игроки в сети, входящие и исходящие приглашения, последние партии пользователя. |
| `POST /api/invites` | Отправить приглашение подключённому игроку: `{"to":"<user-id>"}`. |
| `POST /api/invites/:id/accept` | Принять приглашение, создать партию и определить первый ход. |
| `POST /api/invites/:id/decline` | Отклонить приглашение. |

Приглашение действует 5 минут. Один аккаунт не может начать вторую партию, пока у него есть незавершённая. Идентификаторы не являются секретами, но сервер проверяет участника для каждого действия.

## Партия

| Метод и маршрут | Тело POST и условие |
| --- | --- |
| `GET /api/games/:id` | Позиция, игроки, журнал, состояние куба и доступные первые ходы для активного игрока. Доступ только двум участникам. |
| `POST /api/games/:id/roll` | `{"version":N}`. Только активный игрок до броска; числа генерирует сервер. |
| `POST /api/games/:id/move` | `{"version":N,"from":23,"to":20,"die":3}`. Для входа с бара `from` равен `"bar"`, для вывода `to` равен `"off"`. |
| `POST /api/games/:id/double` | `{"version":N}`. Предложить удвоение до броска при наличии права на куб. |
| `POST /api/games/:id/respond` | `{"version":N,"accept":true}` или `false`. Ответить на предложение соперника. |
| `POST /api/games/:id/resign` | `{"version":N}`. Сдаться, отдав сопернику текущую стоимость куба. |

`version` берётся из последнего ответа `GET /api/games/:id` или успешного действия. При изменившейся позиции сервер возвращает `409`; клиент должен обновить партию и не повторять старое действие вслепую. После каждого подтверждённого действия сервер сохраняет позицию, возвращает её в ответе и рассылает участникам `refresh`. Для проверки ходов используется тот же движок правил, что и в локальной игре. Отмена подтверждённого онлайн-хода не поддерживается.

## Служебные маршруты

- `GET /api/health`: ответ `{"ok":true}` без входа, проверяет запуск процесса.
- `POST /api/logs`: файловый журнал локальных режимов. При заданном `PUBLIC_ORIGIN` требует входа. Тело содержит `session` (32 шестнадцатеричных символа), `game` (номер партии), `kind` и `text`.

Запросы, изменяющие данные, принимаются только с ожидаемого `Origin`, если браузер его передал. Для публичного VPS настройте `PUBLIC_ORIGIN` на точный HTTPS-адрес. Сервер слушает только `127.0.0.1`, внешний доступ должен проходить через HTTPS-прокси.
