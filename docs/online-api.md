# Онлайн API

Все маршруты находятся на том же домене, что и игра. Ответы имеют формат JSON. Ошибка возвращает HTTP-статус и объект `{"error":"..."}`. После входа браузер передаёт сессионную cookie автоматически. Личный токен отправляется только в теле запроса входа и не включается в URL.

## Вход и администрирование

| Метод и маршрут | Назначение |
| --- | --- |
| `POST /api/auth/login` | Вход по `{"token":"nard_..."}`. Возвращает пользователя и устанавливает сессионную cookie на 7 дней. |
| `GET /api/auth/me` | Текущий пользователь или `401`, если сессия отсутствует. |
| `POST /api/auth/logout` | Завершить текущую сессию и очистить cookie. |
| `GET /api/admin/users` | Список пользователей без хэшей и токенов. Только администратор. |
| `POST /api/admin/users` | Создать игрока по `{"name":"..."}`. Возвращает личный токен только в этом ответе. |
| `POST /api/admin/users/:id/rotate` | Перевыпустить токен игрока и завершить его сессии. Новый токен возвращается только в этом ответе. |
| `POST /api/admin/users/:id/toggle` | Отключить или включить игрока. Отключение завершает его активную партию в пользу соперника. |

Токены генерируются из 32 случайных байт. В файле `data/state.json` хранятся их SHA-256 хэши. Аккаунт первого администратора создаётся CLI-командой при остановленном сервере, остальные аккаунты создаются в админ-панели.

## Присутствие и приглашения

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/live` | Поток Server-Sent Events. Открытое соединение означает, что пользователь в сети. Событие `refresh` предлагает клиенту снова запросить лобби или партию. |
| `GET /api/lobby` | Игроки в сети, входящие и исходящие приглашения, последние партии пользователя и статистика `stats` (итоги и личный счёт `headToHead`). |
| `POST /api/invites` | Отправить приглашение подключённому игроку: `{"to":"<user-id>","targetPoints":null\|5\|12\|15,"colorMode":"random"\|"light"\|"dark"}`. |
| `POST /api/invites/:id/accept` | Принять приглашение, создать партию/матч и определить первый ход. |
| `POST /api/invites/:id/decline` | Отклонить входящее приглашение. |
| `POST /api/invites/:id/cancel` | Отозвать своё исходящее приглашение. |

Приглашение действует 5 минут. Один аккаунт не может начать вторую партию, пока у него есть незавершённая. Идентификаторы не являются секретами, но сервер проверяет участника для каждого действия.

## Партия

| Метод и маршрут | Тело POST и условие |
| --- | --- |
| `GET /api/games/:id` | Позиция, игроки, журнал, состояние куба, счёт и статус матча (`targetPoints`, `gameNumber`, `score`, `crawford`, `readyNext`), `lastRoll`, `lastTurn`, `claimTimeoutAt`, `opponentOnline`, `rematchInvite` и доступные первые ходы. Доступ только двум участникам. |
| `POST /api/games/:id/roll` | `{"version":N}`. Только активный игрок до броска; числа генерирует сервер. |
| `POST /api/games/:id/turn` | `{"version":N,"moves":[...]}`. Подтвердить полную последовательность шагов хода после локального подбора с отменой. |
| `POST /api/games/:id/move` | `{"version":N,"from":23,"to":20,"die":3}`. Пошаговый ход (обратная совместимость). Для входа с бара `from` равен `"bar"`, для вывода `to` равен `"off"`. |
| `POST /api/games/:id/double` | `{"version":N}`. Предложить удвоение до броска при наличии права на куб (кроме партии Кроуфорда и «мёртвого» куба). |
| `POST /api/games/:id/respond` | `{"version":N,"accept":true}` или `false`. Ответить на предложение соперника. |
| `POST /api/games/:id/next` | `{"version":N}`. Подтвердить готовность к следующей партии внутри матча (фаза `game_over`). |
| `POST /api/games/:id/resign` | `{"version":N,"scope":"game"\|"match"}`. Сдаться в текущей партии или во всём матче, отдав сопернику текущую стоимость куба. |
| `POST /api/games/:id/claim-timeout` | `{"version":N}`. Завершить зависшую партию победой по таймауту неактивности соперника (по умолчанию 5 минут, `GAME_INACTIVITY_MINUTES`). |

`version` берётся из последнего ответа `GET /api/games/:id` или успешного действия. При изменившейся позиции сервер возвращает `409`; клиент должен обновить партию и не повторять старое действие вслепую. После каждого подтверждённого действия сервер сохраняет позицию, возвращает её в ответе и рассылает участникам `refresh`. Для проверки ходов используется тот же движок правил, что и в локальной игре. В интерфейсе игрок собирает шаги своего хода локально с возможностью отмены и отправляет их целиком через `/turn`.

`lastRoll` содержит уникальный `id`, тип `kind` (`opening` или `turn`), цвет бросившего `player`, два значения `dice` и время `at`. Для первого броска `dice` содержит по одному результату светлых и тёмных, а `player` указывает, кто начинает. Клиент запускает анимацию только при изменении `lastRoll.id`; исход броска всегда приходит с сервера.

`lastTurn` содержит `{player, rollId, moves}` с перемещениями текущего или последнего сыгранного хода (либо `null`, если ходов ещё не было или предыдущий ход был пропущен) и используется интерфейсом для подсветки последнего хода.

## Служебные маршруты

- `GET /api/health`: ответ `{"ok":true}` без входа, проверяет запуск процесса.
- `POST /api/logs`: файловый журнал локальных режимов. На публичном домене требует входа; на `localhost` и `127.0.0.1` доступен без него. Тело содержит `session` (32 шестнадцатеричных символа), `game` (номер партии), `kind` и `text`.

Запросы, изменяющие данные, принимаются только с ожидаемого `Origin`, если браузер его передал. Для публичного VPS настройте `PUBLIC_ORIGIN` на точный HTTPS-адрес. Сервер слушает только `127.0.0.1`, внешний доступ должен проходить через HTTPS-прокси.
